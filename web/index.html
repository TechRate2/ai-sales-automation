Connection guide

Lấy thông tin ở đâu

Theo tài liệu đã xác minh

Botcake

  1. `BOTCAKE_PAGE_ID` có thể nhập thủ công từ page/bot đang dùng trong Botcake.
  2. Nếu `BOTCAKE_API_TOKEN` là JWT có field `id`, hệ thống sẽ tự suy ra Page ID khi `BOTCAKE_PAGE_ID` để trống.
  3. Lấy `BOTCAKE_API_TOKEN` trong khu vực Developer/API của Botcake admin.
  4. Dùng header `access-token` khi gọi Public API.
  5. Dùng `GET /pages/{page_id}/get_list_tag` để lấy tag ID.
  6. Dùng `POST /pages/{page_id}/flows/send_content` và `send_flow` để gửi tin/flow.

Botcake Public API vẫn dùng `page_id` trong URL; tự suy ra từ token là tiện ích cấu hình, không thay thế bước xác minh page/bot thật.

Pancake Inbox

  1. `PANCAKE_API_PAGE_ACCESS_TOKEN` dùng để đọc conversations, messages, tags và customers của page.
  2. `PANCAKE_API_USER_ACCESS_TOKEN` dùng để tự list page hoặc generate page token khi có xác nhận.
  3. Nếu chỉ kết nối page hiện tại, ưu tiên lấy Page Access Token và điền `PANCAKE_API_PAGE_ID`.
  4. Không tự regenerate Page Access Token nếu chưa có xác nhận của chủ dự án.

POS `api_key` không thể thay thế Pancake `page_access_token` cho Unified Inbox.

Pancake POS

  1. Vào Cấu hình → Nâng cao → Kết nối bên thứ 3 → Webhook/API.
  2. Tạo `PANCAKE_POS_API_KEY`.
  3. Gọi `GET /shops` để lấy `PANCAKE_POS_SHOP_ID`.
  4. Gọi `GET /shops/{SHOP_ID}/warehouses` để lấy warehouse ID.
  5. Gọi `GET /products/variations` để lấy sản phẩm và biến thể.

Pancake POS dùng `api_key` dạng query theo OpenAPI hiện tại.

Trước khi bật thật

  1. Chạy `npm run doctor` và xử lý mọi `[FAIL]`.
  2. Capture webhook thật từ Botcake.
  3. Kiểm tra sản phẩm/tồn kho thật từ POS.
  4. Không bật đơn nháp nếu chưa xác minh status draft.
  5. Không commit `.env` lên GitHub.
